# 码域CRM 代码说明

> 技术栈：Spring Boot 2.7 / JDK 8 / MyBatis-Plus / Sa-Token / MySQL / Redis（后端）；
> Vue 3 + Element Plus + Vite（PC 端）；uni-app Vue 3（移动端 H5 / 微信小程序 / APP）。
> 规模：后端 6 个 Maven 模块 141 个 Java 文件；PC 27 页；移动端 9 页；数据库 24 张表。

## 1. 模块划分与依赖关系

```
freecrm-common（零业务依赖）
   ↑
freecrm-system（RBAC/通知/短信/日志）
   ↑           ↑
freecrm-oa ────┘（审批流引擎，依赖 system）
   ↑
freecrm-crm（CRM 业务，依赖 system + oa）
freecrm-eam（EAM 资产，依赖 system + oa）
   ↑
freecrm-server（Spring Boot 装配，聚合全部模块打包 fat jar）
```

前端两个工程独立：`freecrm-web`（PC）、`freecrm-app`（uniapp 移动端），均通过 `/api/**` 与后端交互。

## 2. freecrm-common（公共基座，5 个类）

| 类 | 职责 |
|----|------|
| `result/R<T>` | 统一响应包装：`{code, msg, data}`，code=0 成功、400/401/403/500 业务错误 |
| `exception/BizException` | 业务异常，构造可带 HTTP 语义 code |
| `entity/BaseEntity` | 实体基类：id（雪花自增）+ createTime/updateTime 自动填充 + creator + `@TableLogic deleted` 逻辑删除 |
| `flow/FlowCallback` | 审批回调接口：`bizType() / onPassed(bizId) / onRejected(bizId)`。放 common 是为切断 crm↔oa 循环依赖 |
| `log/OpLog` | 操作日志注解（模块/动作），切面在 system 模块 |

## 3. freecrm-system（系统与平台能力，47 个类）

### 3.1 认证与 RBAC
- `controller/AuthController`：`/api/auth/login`（BCrypt 校验 + Sa-Token 发 token + 返回权限与菜单树）、`logout`、`me`
- `auth/StpInterfaceImpl`：Sa-Token 权限数据源。**超管角色 code=super_admin 直接返回 `["*"]` 通配**
- `service/impl/AuthServiceImpl`：登录同时写 `sys_login_log`（成功/失败/IP）
- 权限模型：`sys_user` ↔ `sys_user_role` ↔ `sys_role` ↔ `sys_role_menu` ↔ `sys_menu`（菜单 type=1 目录 / 2 页面 / 3 按钮，按钮不进侧栏只贡献权限码）

### 3.2 平台能力
| 组件 | 说明 |
|------|------|
| `service/NoticeService` | 站内信：send / 我的消息 / 未读数 / 已读 |
| `service/SmsService` | 阿里云短信：配置存 `sys_config` 后台可改（AccessKey 脱敏），失败不影响主业务 |
| `service/ConfigService` | sys_config 键值读写（公海回收规则、短信参数） |
| `handler/OpLogAspect` | `@OpLog` 注解切面 → `sys_oper_log`（含异常与耗时） |
| `handler/SeedRunner` | 首次启动种子：根部门/super_admin/admin/全部菜单（菜单表非空则跳过，幂等） |
| `controller/LogController` | 操作日志 / 登录日志查询 |
| `controller/SmsController` | 短信配置读写、测试发送、发送记录 |

## 4. freecrm-oa（审批流引擎，13 个类）

核心是 `service/FlowEngine`（自研，无 Flowable 依赖），三张表：`oa_flow_def`（定义）/ `oa_flow_instance`（实例）/ `oa_flow_task`（任务）。

### 4.1 节点模型（nodes JSON，存在 oa_flow_def.nodes）
```json
[
  {"level":1,"name":"销售经理","signType":"ANY","approverUserIds":[2]},
  {"level":2,"type":"CONDITION","name":"金额分支","branches":[
      {"expr":"amount >= 50000","goto":3},{"default":true,"goto":4}]},
  {"level":3,"name":"总监会签","signType":"ALL","approverUserIds":[2,8]},
  {"level":4,"name":"总经理","signType":"ANY","approverUserIds":[1]}
]
```
- **APPROVAL 节点**：`signType=ANY`（或签，任一人通过即过级，其余任务自动关闭）；`ALL`（会签，全部通过才推进，多人任务并行等待）
- **CONDITION 节点**：无审批人。表达式求值（`变量 op 数字`，`&&` 组合）命中即 `goto` 跳转；无命中走 default；goto 超过节点总数 = 直接结束。业务变量：合同/回款 `amount`、`contractAmount`、请假 `days`（发起时由调用方传入；审批中途经 `OaBizMapper` 反查业务表，保证条件节点随时可求值）
- 兼容 v1 nodes（无 signType/type 字段时按 ANY 顺序流处理）

### 4.2 引擎流程
1. `start(bizType, bizId, title, applicant, vars)`：建实例 → `advanceTo` 沿条件路由到首个 APPROVAL 节点 → 建任务 + **发站内信/短信给审批人**
2. `audit(taskId, pass, opinion)`：驳回 → 关闭同节点任务、实例 REJECTED、通知申请人；通过 → 或签关其余 / 会签等齐 → 推进下一节点（循环条件路由）
3. `finish()`：实例终态 → 按 bizType 路由到 `FlowCallback` 实现回写业务 + 通知申请人
4. 防呆：条件跳转死循环 guard（>50 次）、重复发起拦截、非当前节点任务拦截

### 4.3 回调实现（业务反向写回）
| 回调类 | bizType | 通过后 |
|--------|---------|--------|
| `crm/flow/ContractFlowCallback` | 1 合同 | 合同 auditStatus→2 |
| `crm/flow/PaymentFlowCallback` | 2 回款 | 回款通过 + 合同已回款累计（超总额抛异常回滚） |
| `oa/controller/LeaveController` 内联 | 3 请假 | 请假 auditStatus→1 |
| `eam/flow/EamScrapFlowCallback` | 4 资产报废 | 资产置报废 |

## 5. freecrm-crm（CRM 业务，52 个类）

### 5.1 数据权限（贯穿设计）
`service/TeamService`：`crm_team_member(bizType, bizId, userId, level)`，level 1负责人/2可写/3只读。
- `checkPermission(bizType, bizId, minLevel)`：无记录或级别不足抛 403
- 客户页列表 = 团队成员 bizId 集合过滤；商机/合同/回款权限**跟随所属客户**团队
- 物理删除 SQL（`@Delete` 注解）绕开逻辑删除，避免与唯一索引冲突

### 5.2 业务模块
| Controller | 要点 |
|-----------|------|
| LeadController | 线索 CRUD；`transform()` 转客户 = 建客户 + 建联系人 + 迁移跟进记录 |
| CustomerController | CRUD、转移、公海 put/receive、`check-duplicate`（名称/手机号全等）、`merge`（被并方联系人/跟进/商机/合同全量 UPDATE 迁移后删除） |
| CustomerFileController | 多文件上传（UUID 落盘 `file.upload-dir/{customerId}/`，原始名入库）、下载（RFC5987 中文文件名）、删除；上传校验 WRITE、下载校验 READ；`followUpId` 关联跟进附件 |
| FollowUpController | 跟进保存后联动刷新客户 lastContactTime/nextContactTime |
| ContactController | 联系人（决策角色枚举） |
| OpportunityController | 商机、阶段组/阶段维护、`move-stage` 推进、`end` 赢单（联动客户 dealStatus=1）/输单 |
| ContractController | 合同 CRUD（状态机 0草稿1审批中2通过3驳回，编号 HT+日期+随机）；`submit` 有流程则 start(1,...)；合同产品明细 `item/save-batch` 全量重写；回款计划；回款 `payment/save`（前置：合同已过审 + 累计不超总额）→ 有流程 start(2,...)；手动 `audit`（无流程兜底） |
| ProductController | 产品（unit 枚举 1件2套3年4次）与分类树 |
| StatsController | 卡片/30 天趋势/销售排行/商机漏斗；**超管（权限含 `*`）看全局，普通用户按团队范围** |
| ExcelController | easyexcel 导出（客户/线索/合同，走用户数据范围）+ 模板 + 导入（逐行校验、重名跳过） |
| `job/PoolRecycleJob` | `@Scheduled` 每小时：掉保（超 N 天未跟进）/超期（创建超 N 天未成交）自动入公海 + 站内信通知；规则读 sys_config 可配 |

## 6. freecrm-eam（资产管理，20 个类）

- `service/AssetService`：资产状态机（闲置0/在用1/维修2/报废3）
  `闲置—领用/借出→在用—退回→闲置`；`报修→维修—修完→闲置`；`scrap` 有流程走审批（bizType=4，金额入变量）无流程直废
  每次变更写 `eam_asset_change`（类型/从到/原因/时间）
- `service/CheckService`：盘点 = 按范围快照账面状态 → 逐项实盘（状态/保管人/盘亏）自动判差 → 差异计数 → 完成归档
- `job/DepreciationJob`：直线法折旧（残值 5%），每月 1 日 cron 幂等生成上月；净值≤残值停提；支持手动按月生成
- 注意 `@Lazy FlowEngine` 注入：切断 Engine→ScrapCallback→AssetService→Engine 循环依赖

## 7. freecrm-server（装配，4 个类）

| 类 | 职责 |
|----|------|
| `FreeCrmApplication` | `@SpringBootApplication(scanBasePackages="com.freecrm")` + `@MapperScan("com.freecrm.**.mapper")` + `@EnableScheduling` |
| `SaTokenWebConfig` | 拦截 `/api/**`，放行 `/api/auth/login` |
| `MybatisPlusConfig` | 分页插件 |
| `JacksonConfig` | LocalDateTime `yyyy-MM-dd HH:mm:ss`、Long→String（防前端精度丢失） |
| `handler/GlobalExceptionHandler` | BizException→code 映射（401/403/400/500），兜底 500 |

配置：`application.yml`（开发）；`application-prod.yml`（生产模板：库名 oa_crm、日志落盘、上传目录）。
生产用 jar 同目录 `application.yml` **外部覆盖**（优先级高于包内）。

## 8. 前端架构

### freecrm-web（PC，27 页）
- `api/request.js`：axios 封装，token 注入（localStorage）、`r.code===0` 直返 data、401 清 token 跳登录
- `store/user.js`：pinia 持久化 token/nickname/menus/permissions
- `router/index.js`：守卫（无 token→/login；**刷新后用 localStorage 菜单重装动态路由**，修 F5 白屏）
- `layout/dynamic.js`：`installDynamicRoutes(menus)` 按后端菜单树 addRoute，`import.meta.glob` 解析 component 字符串
- `layout/index.vue`：侧栏菜单 + 顶栏**铃铛未读数**（30s 轮询）+ 用户下拉
- 页面按 `views/{crm,oa,eam,system}/{模块}/index.vue` 组织，与菜单表 component 字段对应

### freecrm-app（移动端，9 页）
- `api/request.js`：uni.request Promise 封装；`BASE_URL`：H5 恒空串（同域部署走 nginx /api 反代），小程序/APP 填绝对地址（`PROD_BASE`）
- `pages.json`：4 个 tabBar（客户/待办/资产/我的）+ 子页面（客户详情/审批详情/消息）
- 条件编译：`#ifdef H5` 走 fetch/FormData（多文件、下载），`#ifndef H5` 走 uni.chooseFile/uni.uploadFile/uni.downloadFile
- `manifest.json`：h5.router.base=/m/（nginx 部署子路径）、mp-weixin appid

## 9. 关键横切约定

1. **响应统一**：所有接口返回 `R<T>`；前端按 code 处理（业务错误也走 HTTP 200）
2. **逻辑删除**：全表 `deleted` 字段 + `@TableLogic`；团队/流程任务等带唯一约束的表用物理删除 SQL
3. **ID 前端转字符串**（Jackson 全局），避免 JS 精度丢失 — 前端比较 ID 时注意类型
4. **业务时间**：LocalDateTime 统一 `yyyy-MM-dd HH:mm:ss`
5. **审批接入三步**：业务方 `flowEngine.start(bizType, id, title, uid, vars)` → 实现 `FlowCallback(bizType)` → 回调里写终态
6. **新菜单**：SeedRunner 加种子（全新库自动有）+ 存量库跑 `sql/freecrm-*-menu.sql`（幂等 INSERT ON DUPLICATE）
